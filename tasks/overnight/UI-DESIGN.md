## Reference decisions
- Linear reference: adopt quiet surface elevation, restrained controls, and clear information density; reject violet branding, display-size marketing heroes and glow.
- IBM/Carbon reference: retain the project's actual IBM Plex typography, consistent 8px rhythm, purposeful labels and visible keyboard focus; do not copy Carbon's exact palette/layout or IBM branding.
- Keep AppDNA's own sage signal color on a slate/navy canvas. Coral is reserved for errors/limitations, not decoration.

## Implementation boundaries
- Preserve request payloads, field names, input semantics, upload behavior, continuation safeguards and evidence statuses.
- One shared workspace header, an introduction no larger than necessary, a structured assessment form, and a bounded scrollable recent-run list.
- Project evidence gets a wider canvas, tighter heading hierarchy and uniform surfaces; article text stays complete and readable.
- No fabricated statistics, scores, sample runs, testimonials or procurement approvals.
- All product and video-facing text is English. Do not modify the original VoiceCue repository.
- Visual preparation can run alongside media processing. Final AppDNA experiment recording remains gated on completed UI/browser QA and the narrative/report checks.

## Acceptance
- Real browser at 320, 768, 1024 and 1440px: no page-wide overflow; form controls labeled and keyboard reachable.
